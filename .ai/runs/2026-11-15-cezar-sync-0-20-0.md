# Execution plan — sync the PWA to Cezar v0.20.0 (2e6b2fd)

Issue: #133

## Goal

Pin the vendored contract to Cezar 0.20.0 (npm `gitHead` / tag `v0.20.0` = `2e6b2fd53c779f03d99cb81ffe0c579a53102ae3`), bump `TESTED_CEZAR_VERSION` to `0.20.0`, port the `attention.ts` delta (the `info` tone for runs waiting on a person), and record the 0.19.0 → 0.20.0 delta in `docs/CEZAR_API.md`.

## Scope

- `packages/cezar-contract/` via `npm run sync:contract 2e6b2fd53c779f03d99cb81ffe0c579a53102ae3` (no hand edits).
- `apps/pwa/src/config/cezar-compat.ts` and the tests that name the tested version.
- `packages/shared/src/attention.ts` (+ tests): `waiting`, `review`, an unanswered ask and a pending permission move to the new `info` tone.
- The PWA status badge tone mapping and a light/dark `--info` token.
- `docs/CEZAR_API.md`.

## Non-goals

- Managers (Manager mode, manager chats, approvals, automation reports), `runClosure()` / `closingStepId()` (the PWA has no step rail or Graph tab), repo-local agent commands, dispatch `account`, telemetry events.
- The host upgrade (handled outside this run). No Cezar restart. No merge.

## Implementation Plan

### Phase 1: Contract sync

1. Run the sync script at the 0.20.0 sha; confirm the vendored diff is limited to what upstream changed.
2. Bump `TESTED_CEZAR_VERSION` and the tests that name it.

### Phase 2: Port upstream changes

1. Port the `info` tone into `packages/shared/src/attention.ts` with table-driven tests.
2. Map `info` in the PWA status badge with a light/dark token; confirm the sidecar does not read tones.

### Phase 3: Docs

1. Add the 0.19.0 → 0.20.0 delta to `docs/CEZAR_API.md`.

## Risks

- A tone the PWA does not map would render an unstyled badge; prevented at compile time: `TONE_CLASS` is a `Record<AttentionTone, string>`.
- 0.20.0 makes the cockpit itself installable (`/manifest.webmanifest`, `start_url: "/"`, no service worker). Our manifest and SW are scoped to `/m/`, so the two installs do not overlap; noted in the docs.
